## Основная идея

> [!tip] Простыми словами: PostgreSQL хранит записи, `DatabaseService` достаёт их, ViewModel кладёт их в коллекцию, а Avalonia показывает таблицу через Binding.

Этот раздел не про SQL сам по себе, а про то, как база данных встраивается в MVVM-приложение на Avalonia.

## База данных в MVVM

> [!tip] Простыми словами: View показывает таблицу, ViewModel командует, Model описывает запись, DatabaseService работает с PostgreSQL.

Обычно структура такая:

```text
MainWindow.axaml
→ интерфейс
MainWindowViewModel
→ команды, свойства, координация
CalculationRecord
→ модель одной записи
DatabaseService
→ соединение и SQL
```

ViewModel:

```csharp
private readonly DatabaseService _databaseService;

public ObservableCollection<CalculationRecord> Records
{
    get;
} = new();
```

Конструктор:

```csharp
public MainWindowViewModel()
{
    _databaseService = new DatabaseService();
    CalculateCommand =
        new RelayCommand(
            async () => await CalculateAsync());
    LoadCommand =
        new RelayCommand(
            async () => await LoadAsync());
}
```

## Сохранение результата из ViewModel

> [!tip] Простыми словами: ViewModel проверяет ввод, считает результат, просит сервис сохранить и обновляет таблицу.

```csharp
private async Task CalculateAsync()
{
    if (!double.TryParse(Input, out double number))
    {
        Result = "Введите число";
        return;
    }

    double square = number * number;
    Result = square.ToString();
    await _databaseService.SaveAsync(
        number,
        square);
    await LoadAsync();
}
```

Логика:

```text
проверяем ввод
→ вычисляем
→ показываем результат
→ сохраняем в PostgreSQL
→ заново загружаем таблицу
```

## Загрузка в ObservableCollection

> [!tip] Простыми словами: `ObservableCollection` — список, который сам сообщает интерфейсу, что в нём появились или исчезли элементы.

```csharp
private async Task LoadAsync()
{
    List<CalculationRecord> records =
        await _databaseService.LoadAsync();

    Records.Clear();
    foreach (CalculationRecord record in records)
    {
        Records.Add(record);
    }
}
```

Почему `ObservableCollection`:

Она уведомляет интерфейс, когда элементы добавляются или удаляются.

Это позволяет `DataGrid` обновляться.

## Вывод таблицы в Avalonia

> [!tip] Простыми словами: `DataGrid` берёт строки из `Records` и показывает их как таблицу на экране.

```xml
<DataGrid ItemsSource="{Binding Records}"
          AutoGenerateColumns="False">
    <DataGrid.Columns>
        <DataGridTextColumn
            Header="ID"
            Binding="{Binding Id}" />
        <DataGridTextColumn
            Header="Ввод"
            Binding="{Binding InputValue}" />
        <DataGridTextColumn
            Header="Результат"
            Binding="{Binding ResultValue}" />
        <DataGridTextColumn
            Header="Время"
            Binding="{Binding CreatedAt}" />
    </DataGrid.Columns>
</DataGrid>
```

Главное:

```xml
ItemsSource="{Binding Records}"
```

`DataGrid` получает строки из коллекции `Records`.

Это важно, потому что преподаватель уже требовал вывести таблицу именно в приложении, а не только посмотреть её через Query Tool.

## Полная цепочка

```text
Пользователь вводит число
→ Binding записывает его в Input
→ нажимает кнопку
→ ICommand вызывает CalculateAsync
→ выполняется вычисление
→ DatabaseService выполняет INSERT
→ DatabaseService выполняет SELECT
→ записи попадают в ObservableCollection
→ DataGrid показывает записи
```

## Обработка ошибок

> [!tip] Простыми словами: ошибки лучше ловить рядом с действием, чтобы пользователь увидел понятное сообщение, а не падение приложения.

```csharp
private async Task CalculateAsync()
{
    try
    {
        if (!double.TryParse(Input, out double number))
        {
            Result = "Введите число";
            return;
        }

        double square = number * number;
        await _databaseService.SaveAsync(
            number,
            square);
        Result = "Сохранено";
        await LoadAsync();
    }
    catch (PostgresException exception)
    {
        Result = "Ошибка PostgreSQL: "
                 + exception.MessageText;
    }
    catch (NpgsqlException exception)
    {
        Result = "Ошибка подключения: "
                 + exception.Message;
    }
    catch (Exception exception)
    {
        Result = "Ошибка: "
                 + exception.Message;
    }
}
```

Различие:

- `PostgresException` → сервер PostgreSQL вернул ошибку SQL;
- `NpgsqlException` → проблема соединения или провайдера;
- `Exception` → остальные ошибки.

## Что сказать про DatabaseService

DatabaseService инкапсулирует работу с PostgreSQL. Он хранит строку подключения, открывает соединение, выполняет параметризованные SQL-запросы и преобразует строки базы данных в объекты модели. ViewModel вызывает его публичные методы и не содержит деталей работы с БД.

## Что преподаватель может попросить дописать

Наиболее вероятно:

### Добавить сохранение нового поля

Было:

```sql
INSERT INTO calculation_results
    (input_value, result_value)
VALUES
    (@input, @result);
```

Нужно добавить время:

```sql
INSERT INTO calculation_results
    (input_value, result_value, created_at)
VALUES
    (@input, @result, @createdAt);
```

И параметр:

```csharp
command.Parameters.AddWithValue(
    "@createdAt",
    DateTime.Now);
```

### Посчитать количество записей

```sql
SELECT COUNT(*)
FROM calculation_results;
```

### Отсортировать результаты

```sql
ORDER BY result_value DESC;
```

### Получить записи по условию

```sql
WHERE input_value > @minimum;
```

### Вывести записи в DataGrid

```csharp
public ObservableCollection<CalculationRecord>
    Records { get; } = new();
```

```xml
<DataGrid ItemsSource="{Binding Records}" />
```

## Коротко для экзамена

В MVVM SQL не пишут в `MainWindow.axaml.cs`. Работа с PostgreSQL выносится в `DatabaseService`: он открывает соединение, выполняет параметризованные запросы и превращает строки БД в объекты модели. ViewModel вызывает методы сервиса асинхронно, сохраняет результат, загружает записи в `ObservableCollection<CalculationRecord>`, а `DataGrid` получает эту коллекцию через `ItemsSource="{Binding Records}"`.
