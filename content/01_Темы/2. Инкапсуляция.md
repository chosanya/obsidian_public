# Инкапсуляция

## Инкапсуляция

> [!tip] Простыми словами: Инкапсуляция — это когда объект прячет внутренние детали и разрешает пользоваться собой только безопасными способами.

> [!definition]
> Инкапсуляция — это свойство системы, позволяющее объединять данные и действия над ними в рамках класса, а также скрывать детали реализации.

Интуитивно:

Инкапсуляция означает, что объект сам управляет своим состоянием, а внешний код взаимодействует с ним только разрешёнными способами.

**Здесь есть две части.**

**Первая:** данные и методы, которые работают с этими данными, объединяются в одном классе.

**Вторая:** внутреннее устройство класса скрывается от внешнего кода. Пользователь класса видит только разрешённый интерфейс: открытые свойства и методы.

**Пример без нормальной инкапсуляции**

```csharp
public class BankAccount
{
    public decimal Balance;
}
```

Использование:

- BankAccount account = new BankAccount();
- account.Balance = 1000;
- account.Balance = -50000;

Поле Balance открыто. Любая часть программы может записать туда любое значение, включая некорректное.
Сам объект никак не контролирует изменение своего состояния.

**Пример с инкапсуляцией**

```csharp
public class BankAccount
{
    private decimal _balance;
    public decimal Balance
    {
        get => _balance;
    }
    public void Deposit(decimal amount)
    {
        if (amount <= 0)
        {
            return;
        }
        _balance += amount;
    }
    public bool Withdraw(decimal amount)
    {
        if (amount <= 0 || amount > _balance)
        {
            return false;
        }
        _balance -= amount;
        return true;
    }
}
```

Разберём код:

private decimal _balance; -- Это закрытое поле. Оно хранит баланс счёта.
Из внешнего кода нельзя написать: account._balance = -50000;
Компилятор выдаст ошибку, потому что поле имеет модификатор private.

Доступ для чтения предоставляется через свойство:

```csharp
public decimal Balance
{
    get => _balance;
}
```

У свойства есть только get, поэтому прочитать баланс можно: Console.WriteLine(account.Balance);

А присвоить значение напрямую нельзя:
account.Balance = -50000; // ошибка

Изменение баланса выполняется только через методы:

account.Deposit(1000);
account.Withdraw(300);
Методы проверяют данные и не позволяют привести объект в неправильное состояние.

**Где здесь инкапсуляция?**

Во-первых, класс объединяет данные и операции над ними:
private decimal _balance и Deposit(...), Withdraw(...)

Во-вторых, внутреннее поле скрыто: private

В-третьих, внешний код использует публичный интерфейс: Balance, Deposit(...), Withdraw(...)

Он знает, что можно пополнить счёт и снять деньги, но ему не обязательно знать, как именно внутри хранится баланс.

### Интерфейс класса

> [!tip] Простыми словами: Интерфейс класса — это всё, что внешний код может увидеть и вызвать у объекта.

В данном случае под интерфейсом понимается не обязательно конструкция interface из C#.

> [!definition]
> Интерфейс объекта — это совокупность доступных извне элементов класса.

Например:

```csharp
public decimal Balance
public void Deposit(decimal amount)
public bool Withdraw(decimal amount)
```

Это публичный интерфейс класса BankAccount.
Поле private decimal _balance является внутренней деталью реализации.
Таким образом, инкапсуляция — не просто private

**Частая ошибка:**
"Инкапсуляция — это когда всё сделано private" -- Это неполный ответ.

private является одним из инструментов инкапсуляции. Но сама инкапсуляция шире:

- объединение данных и методов в классе;
- сокрытие внутренней реализации;
- предоставление контролируемого доступа;
- защита объекта от некорректного состояния.

Например, этот класс использует private, но почти не управляет состоянием:

```csharp
public class Person
{
    private int _age;
    public void SetAge(int age)
    {
        _age = age;
    }
}
```

Метод позволяет записать отрицательный возраст. Формально поле скрыто, но контроль состояния реализован плохо.

Лучше:

```csharp
public class Person
{
    private int _age;
    public int Age
    {
        get => _age;
        set
        {
            if (value >= 0 && value <= 150)
            {
                _age = value;
            }
        }
    }
}
```

Теперь класс контролирует допустимые значения.

### Модификаторы доступа

> [!tip] Простыми словами: Модификаторы доступа отвечают на вопрос: кому можно трогать этот элемент кода.
Для инкапсуляции нужно понимать основные модификаторы:

private --- Элемент доступен только внутри своего класса.

public --- Элемент доступен из внешнего кода.

protected --- Элемент доступен внутри класса и в классах-наследниках.

internal --- Элемент доступен внутри текущей сборки или проекта.

На текущем этапе критично запомнить прежде всего private и public.

### Инкапсуляция в вашем Avalonia-проекте

> [!tip] Простыми словами: В Avalonia инкапсуляция помогает прятать внутренние поля и работу с БД за понятными свойствами и методами.

```csharp
Она будет встречаться в ViewModel:
private string _result = string.Empty;
public string Result
{
    get => _result;
    set
    {
        _result = value;
        OnPropertyChanged();
    }
}
```

Поле _result скрыто.
Свойство Result предоставляет доступ к данным и дополнительно уведомляет интерфейс об изменении.
То есть внешний код не должен напрямую изменять _result. Он работает со свойством Result.

```csharp
Инкапсуляция будет и в сервисе БД:
public class DatabaseService
{
    private readonly string _connectionString;
    public async Task SaveResultAsync(double value)
    {
        // Внутренняя работа с соединением и SQL
    }
}
```

Другие части программы вызывают: await databaseService.SaveResultAsync(result);

Они не обязаны знать:

- как открывается соединение;
- какая SQL-команда создаётся;
- как передаются параметры;
- как закрывается соединение.

Эти детали скрыты внутри DatabaseService.

**Итог:**
Инкапсуляция — это принцип ООП, при котором данные и действия над ними объединяются внутри класса, а детали реализации скрываются от внешнего кода.
Доступ к состоянию объекта предоставляется через открытые свойства и методы. Например, поле баланса можно сделать private, а изменение баланса выполнять через методы пополнения и снятия, которые проверяют корректность операции.

**Короткий ответ на 30 секунд**

Инкапсуляция — это объединение данных и методов работы с ними в одном классе и сокрытие внутренней реализации.
Обычно поля делают private, а внешний доступ предоставляют через public-свойства и методы. 
Это позволяет контролировать изменения и не допускать некорректного состояния объекта.
