# Абстрактные классы и интерфейсы

## Абстрактные классы и интерфейсы

> [!tip] Простыми словами: Обе конструкции задают общий тип, но абстрактный класс даёт базу, а интерфейс задаёт обещание.

Обе конструкции задают общий тип для нескольких классов, но делают это по-разному.

Абстрактный класс обычно используют, когда у объектов есть общая база: общие поля, свойства, методы и часть готовой реализации.

Интерфейс используют, когда нужно задать обязательный набор возможностей — контракт, который класс должен выполнить.

### Абстрактный класс

> [!tip] Простыми словами: Абстрактный класс — это заготовка для родственных классов, из которой нельзя создать объект напрямую.

Абстрактный класс объявляется через abstract:

```csharp
public abstract class Animal
{
    public string Name { get; set; }
    public void Eat()
    {
        Console.WriteLine("{Name} ест");
    }
    public abstract void MakeSound();
}
```

Здесь: public abstract class Animal, означает, что Animal — абстрактный класс.

- Из него нельзя напрямую создать объект: Animal animal = new Animal(); // ошибка
- Абстрактный класс **предназначен** для наследования.
- Внутри него могут быть обычные элементы с готовой реализацией:

```csharp
public void Eat()
{
    Console.WriteLine("{Name} ест");
}
```

А также абстрактные методы: public abstract void MakeSound();

> [!definition]
> Абстрактный метод:
> 
> - не имеет тела;
> - задаёт обязательную операцию;
> - должен быть реализован в производном классе через override.

Производный класс:

```csharp
public class Dog : Animal
{
    public override void MakeSound()
    {
        Console.WriteLine("Гав");
    }
}

Теперь объект создать можно:
-- Dog dog = new Dog();
-- dog.Name = "Шарик";
-- dog.Eat();
-- dog.MakeSound();

Результат:

Шарик ест

Гав
```

Класс Dog получил готовый метод Eat() и самостоятельно реализовал обязательный метод MakeSound().

**(!)** Если Dog не реализует абстрактный метод, он тоже должен быть объявлен абстрактным.

#### Когда нужен абстрактный класс

Когда классы действительно являются родственными сущностями и имеют общее состояние или реализацию.

Например:
-- Animal → Dog, Cat; 
-- Shape → Circle, Rectangle; 
-- Employee → Manager, Programmer.

Можно вынести общее состояние:

```csharp
public abstract class Shape
{
    public string Name { get; set; }
    public abstract double CalculateArea();
    public void PrintName()
    {
        Console.WriteLine(Name);
    }
}
```

Производный класс:

```csharp
public class Circle : Shape
{
    public double Radius { get; set; }
    public override double CalculateArea()
    {
        return Math.PI * Radius * Radius;
    }
}
```

### Интерфейс

> [!tip] Простыми словами: Интерфейс — это список требований: класс обязан реализовать указанные возможности.

> [!definition]
> Интерфейс задаёт контракт: какие элементы должен иметь класс.
> 
> Контракт — это обещание класса: «если я реализую этот интерфейс, у меня точно будут указанные методы, свойства и события».

```csharp
public interface IPrintable
{
    void Print();
}
```

По соглашению имена интерфейсов в C# начинаются с I.
#### IPrintable
IPrintable можно читать как: Объект можно печатать.

Класс реализует интерфейс:

```csharp
public class Report : IPrintable
{
    public void Print()
    {
        Console.WriteLine("Печать отчёта");
    }
}
```

Запись: "Report : IPrintable"
означает, что класс обязуется реализовать элементы интерфейса.

Если метод Print() не будет реализован, класс не скомпилируется.

#### Интерфейс как тип

Переменная интерфейсного типа может хранить объект класса, реализующего этот интерфейс:

```csharp
IPrintable printable = new Report();
printable.Print();
```

Это полиморфизм через интерфейс.

Разные классы могут реализовывать один интерфейс:

```csharp
public class Document : IPrintable
{
    public void Print()
    {
        Console.WriteLine("Печать документа");
    }
}
public class Photo : IPrintable
{
    public void Print()
    {
        Console.WriteLine("Печать фотографии");
    }
}
List<IPrintable> items = new List<IPrintable>
{
    new Document(),
    new Photo()
};
foreach (IPrintable item in items)
{
    item.Print();
}
```

Каждый объект выполняет одну операцию по-своему.

### Несколько интерфейсов

> [!tip] Простыми словами: Класс может подписаться сразу на несколько наборов требований.

Класс в C# может наследоваться только от одного класса, но реализовывать несколько интерфейсов:

```csharp
public interface IPrintable
{
    void Print();
}
public interface ISavable
{
    void Save();
}
public class Report : IPrintable, ISavable
{
    public void Print()
    {
        Console.WriteLine("Печать");
    }
    public void Save()
    {
        Console.WriteLine("Сохранение");
    }
}
```

**Это важное различие:** 
Один базовый класс -- Несколько интерфейсов

### Абстрактный класс и интерфейс: разница

> [!tip] Простыми словами: Если нужна общая реализация — чаще абстрактный класс; если нужен только контракт — интерфейс.

Абстрактный класс может содержать:

- поля;
- свойства;
- конструкторы;
- обычные методы;
- виртуальные методы;
- абстрактные методы;
- общее состояние.

Интерфейс прежде всего задаёт контракт: какие возможности должен предоставить тип.

### Итог

> [!tip] Простыми словами: Главное: абстрактный класс помогает наследникам общей базой, интерфейс помогает работать с разными классами одинаково.

Абстрактный класс используется для общей базы родственных классов и может содержать состояние и готовую реализацию. Интерфейс задаёт контракт — набор обязательных элементов, которые класс должен реализовать. Класс может наследоваться только от одного класса, но реализовывать несколько интерфейсов.

Очень важная оговорка

В современных версиях C# интерфейсы могут содержать реализации некоторых членов. Но для экзамена лучше не начинать с этого, если преподаватель отдельно не спросил.

Основная идея остаётся такой:
-- Абстрактный класс — общая база и частичная реализация. 
-- Интерфейс — общий контракт.

### Связь с ICommand

> [!tip] Простыми словами: `ICommand` — пример интерфейса: кнопке важно, что команду можно выполнить, а не какой у неё конкретный класс.

В MVVM кнопка обычно привязывается к свойству типа ICommand.

```csharp
public ICommand CalculateCommand { get; }
```

ICommand — интерфейс. Он требует наличие основных элементов:

```csharp
bool CanExecute(object? parameter);
void Execute(object? parameter);
event EventHandler? CanExecuteChanged;
```

т.о. Класс `RelayCommand` реализует интерфейс `ICommand` и поэтому обязан предоставить его элементы: `CanExecute`, `Execute` и событие `CanExecuteChanged`.

Класс команды реализует этот интерфейс:

```csharp
public class RelayCommand : ICommand
{
    private readonly Action _execute;
    public RelayCommand(Action execute)
    {
        _execute = execute;
    }
    public bool CanExecute(object? parameter)
    {
        return true;
    }
    public void Execute(object? parameter)
    {
        _execute();
    }
    public event EventHandler? CanExecuteChanged;
}
```

Главная мысль: 
- Интерфейс ICommand сообщает Avalonia, что объект можно использовать как команду кнопки. 
- ViewModel не обязана зависеть от конкретного класса RelayCommand. Она работает через общий тип:

```csharp
public ICommand CalculateCommand { get; }
```

А внутри может находиться объект:

```csharp
CalculateCommand = new RelayCommand(Calculate);
```

-- Слева — интерфейсный тип ICommand.

-- Справа — конкретная реализация RelayCommand.

ViewModel зависит от общего контракта `ICommand`, а не от конкретного класса `RelayCommand`. Поэтому реализацию команды можно заменить, не меняя тип свойства и привязку в интерфейсе.

### Итог

> [!tip] Простыми словами: Главное: абстрактный класс помогает наследникам общей базой, интерфейс помогает работать с разными классами одинаково.

**Про абстрактный класс:** 
Абстрактный класс — это класс, экземпляр которого нельзя создать напрямую. Он служит базой для производных классов и может содержать как готовую реализацию, так и абстрактные методы, которые потомки обязаны переопределить.

**Про интерфейс:** 
Интерфейс задаёт контракт: набор элементов, которые реализующий класс обязан предоставить. Через интерфейс можно работать с разными объектами единообразно. Класс может реализовать несколько интерфейсов.

**Главное отличие**
Абстрактный класс задаёт общую базу для родственных классов и может содержать поля, состояние, конструкторы и готовую реализацию методов. Интерфейс задаёт контракт — набор элементов, которые класс обязан реализовать.

**короче** Абстрактный класс — общая база и частичная реализация. Интерфейс — обязательный контракт.
