## Основная идея

> [!tip] Простыми словами: Асинхронность — это когда программа умеет ждать, но не заставляет всё окно стоять на месте.


В Avalonia это особенно важно для:

- вычислений, которые занимают время;
- запросов к базе данных;
- загрузки файлов;
- сетевых запросов;
- любых действий, где пользователь не должен смотреть на зависшее окно.

## Пример async-метода

```csharp
private async Task CalculateAsync()
{
    Result = "Считаю...";
    await Task.Delay(2000);
    Result = "Готово";
}
```

## Что здесь происходит

> [!tip] Простыми словами: Метод сначала пишет “Считаю...”, потом спокойно ждёт, а окно в это время остаётся живым.

- `async` разрешает использовать `await`;
- `Task` означает, что метод представляет асинхронную операцию;
- `await Task.Delay(2000)` ждёт 2 секунды;
- во время ожидания окно не зависает;
- после ожидания код продолжается.

`Result = "Считаю..."` сразу меняет свойство. Если в сеттере вызывается `OnPropertyChanged()`, Binding сообщает интерфейсу, что текст нужно обновить.

После `await` выполнение метода продолжается, и `Result = "Готово"` снова обновляет свойство.

## Асинхронная команда

> [!tip] Простыми словами: Кнопка запускает команду, команда запускает async-метод, а async-метод сам умеет ждать.

Для команды:

```csharp
public ICommand CalculateCommand { get; }

public CalculatorViewModel()
{
    CalculateCommand = new RelayCommand(async () => await CalculateAsync());
}
```

Здесь в `RelayCommand` передаётся лямбда:

```csharp
async () => await CalculateAsync()
```

Она означает: “когда команду вызовут, асинхронно запусти `CalculateAsync()`”.

## Цепочка выполнения

```text
Нажали кнопку
→ команда вызвала CalculateAsync()
→ Result стал "Считаю..."
→ программа ждёт 2 секунды
→ интерфейс остаётся живым
→ Result стал "Готово"
```

### #`Task.Delay` и `Thread.Sleep` 

`Task.Delay` и `Thread.Sleep` оба создают паузу, но ведут себя по-разному.

```csharp
await Task.Delay(1000);
```

-- **Это асинхронная пауза на одну секунду.** Текущий метод временно останавливается, но поток интерфейса не блокируется. Окно продолжает реагировать на нажатия, перемещение и перерисовку. Через секунду выполнение метода продолжается со следующей строки.

```csharp
Thread.Sleep(1000);
```

-- **Это блокирующая пауза.** Текущий поток буквально ничего не делает одну секунду. Если это UI-поток, окно на это время зависнет: кнопки не нажимаются, интерфейс не обновляется.

Пример:

```csharp
private async Task StartAsync()
{
    Result = "Ожидание";

    await Task.Delay(1000);

    Result = "Готово";
}
```

Пользователь сразу увидит `Ожидание`, окно останется рабочим, а через секунду появится `Готово`.

С `Thread.Sleep`:

```csharp
private void Start()
{
    Result = "Ожидание";

    Thread.Sleep(1000);

    Result = "Готово";
}
```

Интерфейс может даже не успеть показать `Ожидание`, потому что UI-поток сразу заблокируется. Через секунду он продолжит работу и покажет `Готово`.

**Запомнить можно так:**

```text
Task.Delay → ждём, но не мешаем интерфейсу
Thread.Sleep → останавливаем поток
```

На экзамене:

`Task.Delay` создаёт асинхронное ожидание и не блокирует UI-поток. `Thread.Sleep` блокирует текущий поток, поэтому при использовании в интерфейсном коде приложение может зависнуть.


## Важно

> [!tip] Простыми словами: Асинхронность — это не обязательно “ещё один поток”. Главное, что программа не затыкает интерфейс ожиданием.

Асинхронность не обязательно означает новый поток. Она означает, что программа не блокирует выполнение во время ожидания.

Например, ожидание базы данных или задержки можно оформить так, чтобы интерфейс продолжал реагировать на пользователя.

В работе с PostgreSQL это встречается постоянно:

```csharp
await _databaseService.SaveAsync(number, square);
await LoadAsync();
```

> [!tip] Простыми словами: приложение ждёт сохранение и загрузку из БД, но окно не зависает.

## Разбор кода

```csharp
private string _result = string.Empty;

public string Result
{
    get => _result;
    set
    {
        _result = value;
        OnPropertyChanged();
    }
}

public ICommand StartCommand { get; }

public MainWindowViewModel()
{
    StartCommand = new RelayCommand(async () => await StartAsync());
}

private async Task StartAsync()
{
    Result = "Запуск";
    await Task.Delay(1000);
    Result = "Завершено";
}
```

Что важно увидеть:

- `StartCommand` — команда, к которой может быть привязана кнопка;
- `RelayCommand` получает async-лямбду;
- `StartAsync()` меняет `Result` два раза;
- `OnPropertyChanged()` нужен, чтобы интерфейс увидел изменения;
- `await Task.Delay(1000)` не блокирует окно во время ожидания.



## Коротко для экзамена

Асинхронность позволяет выполнять долгие операции без заморозки интерфейса. Метод с `async Task` может использовать `await`, чтобы дождаться операции и продолжить выполнение позже. В MVVM асинхронный метод часто запускают через команду, например `new RelayCommand(async () => await StartAsync())`. При изменении свойства ViewModel вызывает `OnPropertyChanged()`, и Binding обновляет интерфейс.
