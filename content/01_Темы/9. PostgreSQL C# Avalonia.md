## Основная идея

> [!tip] Простыми словами: база данных — это тетрадка приложения, куда оно записывает результаты, а потом может снова их прочитать.

В билетах база данных почти всегда нужна для сохранения результатов, времени, параметров или промежуточных шагов. Иногда дополнительно требуется посчитать данные средствами SQL и вывести таблицу прямо в приложении.

## Что такое база данных

> [!tip] Простыми словами: таблица в БД похожа на таблицу в тетради: строки — записи, столбцы — свойства записи.

База данных — организованное хранилище данных.

В PostgreSQL данные обычно лежат в таблицах.

Пример таблицы:

|  id | input_value | result_value | created_at       |
| --: | ----------: | -----------: | ---------------- |
|   1 |           5 |           25 | 2026-06-14 12:00 |
|   2 |           3 |            9 | 2026-06-14 12:05 |

Строка — одна запись.

Столбец — один вид данных.

Например:

- `id` — номер записи;
- `input_value` — введённое число;
- `result_value` — результат;
- `created_at` — время создания.

## PostgreSQL и Npgsql

> [!tip] Простыми словами: PostgreSQL хранит данные, а Npgsql помогает C# с ним разговаривать.

PostgreSQL — система управления базами данных.

Npgsql — библиотека, через которую C# работает с PostgreSQL.

Подключается пространство имён:

```csharp
using Npgsql;
```

Обычно в проект устанавливают пакет:

```text
Npgsql
```

Главные классы:

- `NpgsqlConnection` — соединение с БД;
- `NpgsqlCommand` — SQL-команда;
- `NpgsqlDataReader` — чтение строк результата `SELECT`.

## Строка подключения

> [!tip] Простыми словами: строка подключения — это адрес и пароль от базы, чтобы приложение знало, куда стучаться.

Пример:

```csharp
private const string ConnectionString =
    "Host=localhost;" +
    "Port=5432;" +
    "Database=oop_exam;" +
    "Username=postgres;" +
    "Password=1234";
```

Что означает:

- `Host` — адрес сервера;
- `Port` — порт PostgreSQL, обычно `5432`;
- `Database` — имя базы данных;
- `Username` — пользователь;
- `Password` — пароль.

На экзамене:

Строка подключения содержит данные, необходимые для соединения приложения с PostgreSQL.

Пароль в реальном проекте лучше не хранить прямо в коде, но для экзаменационных проектов это часто упрощают.

## Модель записи

> [!tip] Простыми словами: модель — это C#-версия одной строки из таблицы.

Создадим класс, который соответствует одной строке таблицы:

```csharp
public class CalculationRecord
{
    public int Id { get; set; }
    public double InputValue { get; set; }
    public double ResultValue { get; set; }
    public DateTime CreatedAt { get; set; }
}
```

Один объект `CalculationRecord` — одна запись из таблицы.

## Создание таблицы

> [!tip] Простыми словами: `CREATE TABLE` готовит пустую таблицу, куда потом можно складывать записи.

SQL:

```sql
CREATE TABLE IF NOT EXISTS calculation_results
(
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    input_value DOUBLE PRECISION NOT NULL,
    result_value DOUBLE PRECISION NOT NULL,
    created_at TIMESTAMP NOT NULL
);
```

Разбор:

- `CREATE TABLE` — создать таблицу;
- `IF NOT EXISTS` — создать только в том случае, если таблицы ещё нет;
- `id INTEGER GENERATED ALWAYS AS IDENTITY` — PostgreSQL сам создаёт новый номер записи;
- `PRIMARY KEY` — уникальный идентификатор строки;
- `DOUBLE PRECISION` — число с плавающей точкой;
- `NOT NULL` — значение обязательно;
- `TIMESTAMP` — дата и время.

Код C#:

```csharp
public async Task InitializeAsync()
{
    await using var connection =
        new NpgsqlConnection(ConnectionString);
    await connection.OpenAsync();

    const string sql = """
        CREATE TABLE IF NOT EXISTS calculation_results
        (
            id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
            input_value DOUBLE PRECISION NOT NULL,
            result_value DOUBLE PRECISION NOT NULL,
            created_at TIMESTAMP NOT NULL
        );
        """;

    await using var command =
        new NpgsqlCommand(sql, connection);
    await command.ExecuteNonQueryAsync();
}
```

Логика:

```text
создали соединение
→ открыли соединение
→ создали SQL-команду
→ выполнили команду
```

## await using

> [!tip] Простыми словами: `await using` аккуратно закрывает соединение, даже если работа была асинхронной.

```csharp
await using var connection =
    new NpgsqlConnection(ConnectionString);
```

`using` означает, что **ресурс будет освобождён после окончания работы.**

Для соединения это важно: оно должно корректно закрыться.

`await using` используется для объектов, которые могут освобождаться асинхронно.

На экзамене:

`await using` гарантирует корректное закрытие соединения и команды даже при возникновении ошибки.

## Добавление записи INSERT

> [!tip] Простыми словами: `INSERT` добавляет новую строку в таблицу.

SQL:

```sql
INSERT INTO calculation_results
    (input_value, result_value, created_at)
VALUES
    (@input, @result, @createdAt);
```

`INSERT INTO` добавляет строку.

Параметры:

- `@input`;
- `@result`;
- `@createdAt`.

получат значения из C#.

Код:

```csharp
public async Task SaveAsync(
    double input,
    double result)
{
    await using var connection =
        new NpgsqlConnection(ConnectionString);
    await connection.OpenAsync();

    const string sql = """
        INSERT INTO calculation_results
            (input_value, result_value, created_at)
        VALUES
            (@input, @result, @createdAt);
        """;

    await using var command =
        new NpgsqlCommand(sql, connection);
    command.Parameters.AddWithValue("@input", input);
    command.Parameters.AddWithValue("@result", result);
    command.Parameters.AddWithValue(
        "@createdAt",
        DateTime.Now);

    await command.ExecuteNonQueryAsync();
}
```

Что делает `ExecuteNonQueryAsync`:

```csharp
await command.ExecuteNonQueryAsync();
```

Используется для команд, которые не возвращают таблицу строк:

- `INSERT`;
- `UPDATE`;
- `DELETE`;
- `CREATE TABLE`.

Результат метода — количество затронутых строк.

## Зачем нужны параметры

> [!tip] Простыми словами: параметры — это безопасные коробочки для значений, чтобы не вклеивать текст пользователя прямо в SQL.

Плохо:

```csharp
string sql =
    $"INSERT INTO users(name) VALUES ('{name}')";
```

Пользовательское значение прямо вставляется в SQL. Это может привести к SQL-инъекции и ошибкам с кавычками.

Правильно:

```csharp
const string sql =
    "INSERT INTO users(name) VALUES (@name)";
command.Parameters.AddWithValue("@name", name);
```

На экзамене:

Параметризованный запрос передаёт данные отдельно от текста SQL. Это повышает безопасность и уменьшает риск SQL-инъекций.

## Получение записей SELECT

> [!tip] Простыми словами: `SELECT` достаёт строки из таблицы.

SQL:

```sql
SELECT
    id,
    input_value,
    result_value,
    created_at
FROM calculation_results
ORDER BY id DESC;
```

`SELECT` получает данные.

`ORDER BY id DESC` сортирует от новых записей к старым.

Код:

```csharp
public async Task<List<CalculationRecord>> LoadAsync()
{
    var records = new List<CalculationRecord>();

    await using var connection =
        new NpgsqlConnection(ConnectionString);
    await connection.OpenAsync();

    const string sql = """
        SELECT
            id,
            input_value,
            result_value,
            created_at
        FROM calculation_results
        ORDER BY id DESC;
        """;

    await using var command =
        new NpgsqlCommand(sql, connection);
    await using var reader =
        await command.ExecuteReaderAsync();

    while (await reader.ReadAsync())
    {
        var record = new CalculationRecord
        {
            Id = reader.GetInt32(0),
            InputValue = reader.GetDouble(1),
            ResultValue = reader.GetDouble(2),
            CreatedAt = reader.GetDateTime(3)
        };
        records.Add(record);
    }

    return records;
}
```

Как это работает:

```csharp
await command.ExecuteReaderAsync();
```

выполняет `SELECT` и возвращает объект чтения.

```csharp
while (await reader.ReadAsync())
```

переходит по строкам результата.

```csharp
reader.GetInt32(0)
```

берёт значение первого столбца.

Нумерация начинается с нуля:

- `0` → `id`;
- `1` → `input_value`;
- `2` → `result_value`;
- `3` → `created_at`.

На каждую строку создаётся объект:

```csharp
new CalculationRecord
```

Затем он добавляется в список.

## ExecuteReaderAsync ExecuteNonQueryAsync ExecuteScalarAsync

> [!tip] Простыми словами: один метод для изменения таблицы, один для чтения строк, один для одного числа или значения.

Запомнить:

- `ExecuteNonQueryAsync` → `INSERT`, `UPDATE`, `DELETE`, `CREATE TABLE`;
- `ExecuteReaderAsync` → `SELECT` с несколькими строками и столбцами;
- `ExecuteScalarAsync` → одно значение.

Например, количество записей:

```sql
SELECT COUNT(*)
FROM calculation_results;
```

C#:

```csharp
public async Task<int> GetCountAsync()
{
    await using var connection =
        new NpgsqlConnection(ConnectionString);
    await connection.OpenAsync();

    const string sql = """
        SELECT COUNT(*)
        FROM calculation_results;
        """;

    await using var command =
        new NpgsqlCommand(sql, connection);
    object? value =
        await command.ExecuteScalarAsync();
    return Convert.ToInt32(value);
}
```

В билете с методом простой итерации количество итераций требуется вычислять средствами SQL, поэтому `COUNT(*)` особенно важен.

## Изменение записи UPDATE

> [!tip] Простыми словами: `UPDATE` меняет уже существующую строку.

SQL:

```sql
UPDATE calculation_results
SET result_value = @result
WHERE id = @id;
```

Код:

```csharp
public async Task UpdateAsync(
    int id,
    double result)
{
    await using var connection =
        new NpgsqlConnection(ConnectionString);
    await connection.OpenAsync();

    const string sql = """
        UPDATE calculation_results
        SET result_value = @result
        WHERE id = @id;
        """;

    await using var command =
        new NpgsqlCommand(sql, connection);
    command.Parameters.AddWithValue("@result", result);
    command.Parameters.AddWithValue("@id", id);
    await command.ExecuteNonQueryAsync();
}
```

`WHERE` указывает, какую строку изменять.

Критическая ошибка:

```sql
UPDATE calculation_results
SET result_value = 0;
```

Без `WHERE` изменятся все строки.

## Удаление DELETE

> [!tip] Простыми словами: `DELETE` удаляет строки, поэтому без `WHERE` он особенно опасен.

SQL:

```sql
DELETE FROM calculation_results
WHERE id = @id;
```

Код:

```csharp
public async Task DeleteAsync(int id)
{
    await using var connection =
        new NpgsqlConnection(ConnectionString);
    await connection.OpenAsync();

    const string sql = """
        DELETE FROM calculation_results
        WHERE id = @id;
        """;

    await using var command =
        new NpgsqlCommand(sql, connection);
    command.Parameters.AddWithValue("@id", id);
    await command.ExecuteNonQueryAsync();
}
```

Без `WHERE` будут удалены все записи:

```sql
DELETE FROM calculation_results;
```

## Фильтрация WHERE

> [!tip] Простыми словами: `WHERE` — это условие: какие строки брать, менять или удалять.

```sql
SELECT *
FROM calculation_results
WHERE result_value > 10;
```

Параметризованный вариант:

```sql
SELECT *
FROM calculation_results
WHERE result_value > @minimum;
```

```csharp
command.Parameters.AddWithValue(
    "@minimum",
    minimum);
```

## Сортировка ORDER BY

> [!tip] Простыми словами: `ORDER BY` раскладывает строки в нужном порядке.

По возрастанию:

```sql
ORDER BY result_value ASC;
```

По убыванию:

```sql
ORDER BY result_value DESC;
```

`ASC` можно не писать: это значение по умолчанию.

## Агрегатные функции

> [!tip] Простыми словами: агрегатные функции считают одно итоговое значение по многим строкам.

Количество:

```sql
SELECT COUNT(*)
FROM calculation_results;
```

Среднее:

```sql
SELECT AVG(result_value)
FROM calculation_results;
```

Максимум:

```sql
SELECT MAX(result_value)
FROM calculation_results;
```

Минимум:

```sql
SELECT MIN(result_value)
FROM calculation_results;
```

Сумма:

```sql
SELECT SUM(result_value)
FROM calculation_results;
```

## Группировка GROUP BY

> [!tip] Простыми словами: `GROUP BY` собирает похожие строки в кучки и считает что-то по каждой кучке.

Например, посчитать число запусков по дате:

```sql
SELECT
    DATE(created_at) AS day,
    COUNT(*) AS count
FROM calculation_results
GROUP BY DATE(created_at)
ORDER BY day;
```

`GROUP BY` объединяет строки в группы.

## SQL-инъекция

> [!tip] Простыми словами: SQL-инъекция — это когда пользовательский текст пролезает внутрь команды и меняет её смысл.

SQL-инъекция — внедрение пользовательского текста в SQL-запрос, которое может изменить смысл команды.

Плохой код:

```csharp
string sql =
    $"SELECT * FROM users WHERE name = '{name}'";
```

Правильный:

```csharp
const string sql =
    "SELECT * FROM users WHERE name = @name";
command.Parameters.AddWithValue("@name", name);
```

Главная защита — параметризованные запросы.

## Коротко для экзамена

PostgreSQL — система управления базами данных, а Npgsql — библиотека, через которую C# работает с PostgreSQL. Для соединения используется `NpgsqlConnection`, для SQL-запросов — `NpgsqlCommand`. `INSERT`, `UPDATE`, `DELETE` и `CREATE TABLE` выполняются через `ExecuteNonQueryAsync`, `SELECT` со строками — через `ExecuteReaderAsync`, а одно значение вроде `COUNT(*)` — через `ExecuteScalarAsync`. Запросы лучше делать параметризованными, чтобы не вставлять пользовательский текст прямо в SQL.
