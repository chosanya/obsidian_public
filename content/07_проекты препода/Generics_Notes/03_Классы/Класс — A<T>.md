# Класс — A<T>

## Исходный файл

`Generics/Program.cs`

## Назначение класса

`A<T>` — обобщенный контейнер, который хранит массив элементов типа `T`.

## Ограничение типа

```csharp
class A<T>
    where T : struct, IComparable
```

Факты из кода:

- `T` должен быть значимым типом (`struct`);
- `T` должен реализовывать `IComparable`.

## Поля

```csharp
T []arr;
```

Массив хранит элементы типа `T`.

## Конструктор

```csharp
public A(T [] mas)
{
    arr = (T[]) mas.Clone();
}
```

Конструктор копирует входной массив через `Clone`.

## Индексатор

```csharp
public T this[int i] => arr[i];
```

Индексатор возвращает элемент типа `T`.

## Методы

```csharp
public override string ToString()
{
    return "[" + string.Join ("; ", arr) + "]";
}
```

Метод возвращает строковое представление массива.

## Какие принципы используются

- обобщения;
- инкапсуляция массива;
- индексатор;
- переопределение `ToString`;
- ограничение типа через интерфейс `IComparable`.

## Что сказать на экзамене

`A<T>` позволяет написать один контейнер для разных типов, но сохранить строгую типизацию. Поэтому при обращении к `a1[i]` из `A<int>` возвращается `int`, а не `object`.

## Проблемное место

В коде создается:

```csharp
var a4 = new A<A<int>>([a1, a3]);
```

Но из-за ограничения `where T : struct, IComparable` класс `A<int>` не подходит как `T`, потому что это класс, а не `struct`, и он не реализует `IComparable`.

Факт проверки: сборка временной копии проекта завершилась ошибкой `CS0453` именно на строке `var a4 = new A<A<int>>([a1, a3]);`.
