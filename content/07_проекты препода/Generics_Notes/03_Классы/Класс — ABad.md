# Класс — ABad

## Исходный файл

`Generics/Program.cs`

## Назначение класса

`ABad` показывает менее удачный подход: хранить элементы разных типов в массиве `object[]`.

## Поля

```csharp
object[] arr;
```

Массив хранит элементы как `object`.

## Конструктор

```csharp
public ABad(object[] mas)
{
    arr = (object[])mas.Clone();
}
```

Конструктор копирует входной массив.

## Индексатор

```csharp
public object this[int i] => arr[i];
```

Индексатор возвращает `object`, поэтому вызывающий код не знает точный тип без приведения.

## Методы

```csharp
public override string ToString()
{
    return "[" + string.Join("; ", arr) + "]";
}
```

## Почему класс назван `ABad`

Потому что он демонстрирует проблему: тип теряется. Например:

```csharp
sum2 += (int)ab1[i];
```

Нужно вручную приводить `object` к `int`. Если внутри окажется строка, во время выполнения будет ошибка.

## Что сказать на экзамене

`ABad` показывает, почему generics нужны. Без обобщений компилятор не может заранее проверить типы элементов, и ошибки появляются позже.
