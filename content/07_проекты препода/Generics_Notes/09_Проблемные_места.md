# Проблемные места Generics

## Возможная ошибка компиляции с `A<A<int>>`

В коде есть строка:

```csharp
var a4 = new A<A<int>>([a1, a3]);
```

Но `A<T>` объявлен так:

```csharp
class A<T>
    where T : struct, IComparable
```

`A<int>` является классом, а не структурой, и не реализует `IComparable`. Поэтому это место выглядит противоречиво.

Факт проверки: временная копия проекта не собирается. Ошибка компилятора: `CS0453`, тип `A<int>` должен быть non-nullable value type, чтобы использоваться как параметр `T` в `A<T>`.

## `ABad` смешивает типы

```csharp
var ab1 = new ABad([2, 3, "5.78"]);
```

В массиве лежат `int`, `int` и `string`. Потом код пытается привести каждый элемент к `int`:

```csharp
sum2 += (int)ab1[i];
```

На строке `"5.78"` это приведет к ошибке времени выполнения, если выполнение дойдет до этой точки.

## Классы находятся в `Program.cs`

Для учебного примера это допустимо, но для реального проекта `A<T>` и `ABad` лучше вынести в отдельные файлы.

## Поля без модификатора доступа

```csharp
T []arr;
object[] arr;
```

В C# такие поля являются `private` по умолчанию, но для читаемости лучше писать `private` явно.

## Ограничение `IComparable` не используется внутри класса

`A<T>` требует `IComparable`, но в коде класса нет сравнения элементов. Это может быть заделом для дальнейшей лекции, но в текущем примере ограничение выглядит избыточным.
