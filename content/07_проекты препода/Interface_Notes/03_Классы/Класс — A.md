# Класс — A

## Исходный файл

`Interface/Program.cs`

## Назначение класса

`A` хранит массив целых чисел, умеет клонироваться и сравниваться с другим объектом `A` по сумме элементов массива.

## Поля

```csharp
int[] arr;
```

Поле хранит массив. Модификатор доступа не указан, значит поле приватное по умолчанию для члена класса.

## Индексатор

```csharp
public int this[int i]
{
    get => arr[i];
    set => arr[i] = value;
}
```

Индексатор позволяет читать и менять элементы массива через объект:

```csharp
a1[0] = 10;
```

## Конструктор

```csharp
public A(int[] mas)
{
    arr = (int[])mas.Clone();
}
```

Конструктор копирует входной массив. Это защищает объект от внешнего изменения исходного массива.

## Интерфейсы

```csharp
class A : ICloneable, IComparable
```

Класс реализует два интерфейса.

### `ICloneable`

```csharp
public object Clone()
{
    return new A(arr);
}
```

Метод создает новый объект `A` с копией массива.

### `IComparable`

```csharp
public int CompareTo(object? obj)
```

Метод сравнивает текущий объект с другим `A` по сумме элементов.

## Методы

```csharp
public override string ToString()
{
    return string.Join(", ", arr);
}
```

Возвращает элементы массива строкой.

## Какие принципы ООП используются

- инкапсуляция массива;
- интерфейсы;
- индексатор;
- переопределение `ToString`;
- исключение при неподходящем типе.

## Что сказать на экзамене

`A` реализует интерфейсы, поэтому его можно использовать там, где ожидается `ICloneable` или `IComparable`. Это показывает полиморфизм через интерфейс: метод работает не с конкретной реализацией, а с контрактом.

## Возможные вопросы

### Почему `Clone` возвращает `object`?

Потому что так задан стандартный интерфейс `ICloneable`.

### Что сравнивает `CompareTo`?

Он сравнивает суммы массивов двух объектов `A`.

### Что будет, если передать в `CompareTo` не `A`?

Будет выброшено `ArgumentException`.
