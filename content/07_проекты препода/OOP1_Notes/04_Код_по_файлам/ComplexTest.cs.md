# ComplexTest.cs

## Путь

`TestComplex/ComplexTest.cs`

## Назначение

Файл содержит xUnit-тесты для класса [[Класс — Complex]]. Тесты проверяют создание объектов, перегруженный оператор `+`, оператор `==` и строковое представление комплексных чисел.

## Исходный код

```csharp
﻿namespace TestComplex
{
    public class ComplexTest
    {
        [Fact]
        public void ConstructingTest()
        {
            var c1 = new Complex();
            Assert.Equal(0.0, c1.Re);
            Assert.Equal(0.0, c1.Im);
            var c2 = new Complex(2, 1);
            Assert.Equal(2.0, c2.Re);
            Assert.Equal(1.0, c2.Im);
        }

        [Fact]
        public void OperatorPlusTest()
        {
            var c1 = new Complex(-2.1, 3);
            var c2 = new Complex(0.1, 3.3);
            var c3 = c1 + c2;
            Assert.Equal(new Complex(-2.0, 6.3), c3);
            Assert.True(c3 == new Complex(-2.0, 6.3));
        }

        [Theory]
        [InlineData("0", 0.0, 0.0)]
        [InlineData("1", 1.0, 0.0)]
        [InlineData("i", 0.0, 1.0)]
        [InlineData("-1", -1.0, 0.0)]
        [InlineData("-i", 0.0, -1.0)]
        [InlineData("1+i", 1.0, 1.0)]
        [InlineData("1-i", 1.0, -1.0)]
        [InlineData("2+i", 2.0, 1.0)]
        [InlineData("2-i", 2.0, -1.0)]
        [InlineData("2+2,5i", 2.0, 2.5)]
        [InlineData("2-2,5i", 2.0, -2.5)]
        [InlineData("2,5i", .0, 2.5)]
        [InlineData("-2,5i", .0, -2.5)]
        public void ToStringTest(string expected, double re, double im)
        {
            var c1 = new Complex(re, im);
            Assert.Equal(expected, c1.ToString());
            
        }
    }
}
```

## Разбор по блокам

### Блок 1. `ConstructingTest`

Что делает: проверяет, что конструктор без параметров создает `0 + 0i`, а конструктор с параметрами правильно записывает `Re` и `Im`.

Почему нужен: подтверждает корректность начального состояния объекта.

Какие конструкции C# используются:

- атрибут `[Fact]`;
- создание объекта;
- `Assert.Equal`.

Связанные темы:

- [[Классы и объекты]]
- [[Конструктор]]
- [[Свойство]]

### Блок 2. `OperatorPlusTest`

Что делает: проверяет сложение комплексных чисел через `+` и сравнение через `==`.

Почему нужен: подтверждает, что перегруженные операторы работают по математическому смыслу.

Какие конструкции C# используются:

- перегрузка оператора;
- `Assert.Equal`;
- `Assert.True`.

Связанные темы:

- переопределение операторов;
- сравнение объектов.

### Блок 3. `ToStringTest`

Что делает: проверяет много вариантов строкового представления комплексного числа.

Почему нужен: метод `ToString` содержит много условий, поэтому его удобно проверять набором параметров.

Какие конструкции C# используются:

- `[Theory]`;
- `[InlineData]`;
- параметризованный тест.

Связанные темы:

- виртуальные и переопределенные методы;
- тестирование.

## Что нужно уметь объяснить преподавателю

- Чем `[Fact]` отличается от `[Theory]`.
- Почему `Assert.Equal(new Complex(...), c3)` работает: потому что в `Complex` переопределен `Equals`.
- Почему тесты помогают подтвердить корректность перегруженных операторов.

## Возможные вопросы

### Почему для `ToString` используется `[Theory]`, а не много отдельных `[Fact]`?

Потому что проверяется один и тот же сценарий с разными входными данными.

### Что именно проверяет `Assert.Equal(new Complex(-2.0, 6.3), c3)`?

Он проверяет равенство объектов по `Equals`, а не по ссылке.
