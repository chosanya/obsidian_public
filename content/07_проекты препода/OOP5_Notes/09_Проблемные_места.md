# Проблемные места OOP5

## Весь код находится в одном файле

Для лекционного примера это нормально. Но если проект расширять, лучше разделить демонстрации по методам или классам.

Что может спросить преподаватель:

- как можно улучшить структуру;
- почему сейчас все написано в `Program.cs`.

## Название `DayOfWeek` совпадает со стандартным типом .NET

В .NET уже есть стандартное перечисление `System.DayOfWeek`.

В этом проекте объявлено свое:

```csharp
public enum DayOfWeek : byte
```

Это не обязательно ошибка в учебном примере, но на защите стоит понимать, что имя совпадает со стандартным типом.

## `[Flags]` показан, но почти не используется

В коде объявлено:

```csharp
Weekend = Saturday | Sunday,
```

Но нет дальнейшей проверки флагов, например через `HasFlag`.

TODO: если потребуется расширить пример, можно добавить демонстрацию проверки `Weekend`.

## Значение `0` в `[Flags] enum` не задано

Для флаговых перечислений часто добавляют значение:

```csharp
None = 0
```

В проекте такого значения нет. Это не ломает пример, но может быть вопросом преподавателя.

## В зубчатом массиве длина строк задана выражением

```csharp
i % 3 + 1
```

Это компактно, но не сразу очевидно. Нужно уметь объяснить, что длины строк повторяются по схеме `1, 2, 3, 1, 2, 3`.

## Нет обработки ошибок

Проект не принимает пользовательский ввод, поэтому обработка ошибок здесь не нужна. Но если бы размеры массивов вводились пользователем, понадобились бы проверки.
