# Темы ООП и C# в SmakLivery

## WPF

Факты из кода:

- Проект включает `<UseWPF>true</UseWPF>`.
- Главное окно описано в `MainWindow.xaml`.
- Форма заказа описана в `AddOrEditWindow.xaml`.

Пояснение:

WPF разделяет визуальную часть в XAML и C#-логику в code-behind или ViewModel.

## MVVM

Факты из кода:

- View: `MainWindow`, `AddOrEditWindow`.
- ViewModel: `MainViewModel`, `AddEditViewModel`.
- Model: `Order`, `OrderWithCourier`, `OrderStatus`.

Пояснение:

MVVM нужен, чтобы интерфейс был привязан к данным и командам, а бизнес-логика не находилась полностью в окнах.

Что требует ручной проверки:

- В `AddOrEditWindow` кнопки используют `Click`, поэтому MVVM реализован не полностью чисто.

## Data Binding

Факты из кода:

- `ListView.ItemsSource` привязан к `Orders`.
- `ListView.SelectedItem` привязан к `SelectedOrder`.
- Поля формы привязаны к `Id`, `Address`, `Status`, `CourierId`.
- `ComboBox` получает значения `OrderStatus` через `ObjectDataProvider`.

Пояснение:

Binding позволяет WPF автоматически брать данные из `DataContext`.

Что требует ручной проверки:

- `SelectedOrder` не вызывает `OnPropertyChanged`.
- `Order` не реализует `INotifyPropertyChanged`.
- Для формы это может быть допустимо, потому что значения читаются при сохранении, но для динамического обновления интерфейса уведомлений нет.

## `ICommand`

Факты из кода:

- `RelayCommand` реализует `ICommand`.
- Команды используются для добавления, редактирования, удаления и сохранения.

Пояснение:

`ICommand` позволяет привязать действие интерфейса к методу во ViewModel.

Что требует ручной проверки:

- `DeleteOrder.CanExecute` проверяет `o is Order`, но из списка передается `OrderWithCourier`.

## `async/await`

Факты из кода:

- Работа с БД выполняется через `await`.
- В `App.OnStartup` и `MainWindow.Window_Loaded` используются `async void`.
- В командах используются асинхронные лямбда-выражения.

Пояснение:

`async/await` нужен, чтобы не блокировать интерфейс при обращении к базе данных.

Что требует ручной проверки:

- `async void` сложнее обрабатывать при ошибках.
- `RelayCommand` принимает `Action<object?>`, поэтому асинхронные лямбды фактически становятся `async void`.

## PostgreSQL

Факты из кода:

- Используется база `smaklivery`.
- Строка подключения: `Host=localhost;Username=postgres;Password=postgres;Database=smaklivery`.
- Создаются PostgreSQL enum `order_status` и таблицы `order`, `courier`.

Пояснение:

PostgreSQL хранит заказы и курьеров. Приложение не работает автономно без локальной БД.

## Npgsql

Факты из кода:

- Подключен пакет `Npgsql` версии `10.0.2`.
- Используются `NpgsqlDataSourceBuilder`, `NpgsqlCommand`, `ExecuteReaderAsync`, `ExecuteNonQueryAsync`, `ExecuteScalarAsync`.

Пояснение:

Npgsql — .NET-драйвер для PostgreSQL.

## SQL

Факты из кода:

- Есть `CREATE TYPE` для `order_status`.
- Есть `CREATE TABLE IF NOT EXISTS` для `order` и `courier`.
- Есть `SELECT * FROM "order" JOIN courier ...`.
- Есть `INSERT`, `UPDATE`, `DELETE`.

Пояснение:

SQL-запросы создают структуру БД и выполняют операции с заказами.

## Темы ООП

- Классы и объекты: `Order`, `OrderWithCourier`, ViewModel-классы.
- Инкапсуляция: свойства скрывают поля и состояние объектов.
- Интерфейсы: `ICommand`, `INotifyPropertyChanged`, `IValueConverter`.
- Перечисления: `OrderStatus`.
- Делегаты и лямбда-выражения: `RelayCommand` принимает действия.
- Асинхронное программирование: `Task`, `async`, `await`.
- Коллекции: `ObservableCollection<OrderWithCourier>`.
