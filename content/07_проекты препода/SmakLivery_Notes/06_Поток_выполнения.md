# Поток выполнения SmakLivery

## Старт приложения

Факты из кода:

1. WPF запускает `App`.
2. В `App.xaml` указан `StartupUri="MainWindow.xaml"`.
3. В `App.OnStartup` вызывается `DbHelper.CreateDbAsync()`.
4. Если подключение к БД или создание таблиц завершается ошибкой, показывается `MessageBox`, затем вызывается `Shutdown(1)`.

Пояснение:

Перед показом основного окна приложение пытается подготовить структуру базы данных.

## Открытие главного окна

Факты из кода:

1. Создается `MainWindow`.
2. В поле создается `MainViewModel`.
3. В конструкторе `MainWindow` вызывается `InitializeComponent()`.
4. Затем `DataContext = viewModel`.

Пояснение:

После установки `DataContext` XAML-привязки начинают брать данные и команды из `MainViewModel`.

## Загрузка заказов

Факты из кода:

1. Срабатывает событие `Loaded` у `MainWindow`.
2. Вызывается `Window_Loaded`.
3. Выполняется `await viewModel.LoadOrdersAsync()`.
4. `LoadOrdersAsync()` вызывает `DbHelper.GetOrders()`.
5. `GetOrders()` выполняет SQL-запрос с `JOIN`.
6. Результаты добавляются в `ObservableCollection<OrderWithCourier>`.

Пояснение:

`ObservableCollection` уведомляет WPF, что в коллекции появились элементы, поэтому список в окне обновляется.

## Добавление заказа

Факты из кода:

1. Пользователь выбирает пункт контекстного меню `Новый заказ`.
2. Выполняется команда `AddOrder`.
3. Создается новый `Order` с адресом `Какой-то адрес`.
4. Открывается `AddOrEditWindow`.
5. В окне создается `AddEditViewModel`.
6. При сохранении вызывается `SaveCommand`.
7. Если `Order.Id == 0`, вызывается `DbHelper.AddOrderAsync(Order)`.
8. После закрытия окна список заказов загружается заново.

## Редактирование заказа

Факты из кода:

1. Пользователь выбирает заказ и пункт `Редактировать заказ`.
2. Выполняется команда `EditOrder`.
3. `SelectedOrder` преобразуется в `Order` через `ToOrder()`.
4. Открывается `AddOrEditWindow`.
5. При сохранении вызывается `DbHelper.EditOrderAsync(Order)`.
6. После закрытия окна список заказов загружается заново.

## Удаление заказа

Факты из кода:

1. Пользователь выбирает пункт `Удалить`.
2. В команду передается выбранный элемент списка.
3. Если параметр распознан как `OrderWithCourier`, вызывается `DbHelper.DeleteOrderByIdAsync(order.Id)`.
4. Элемент удаляется из `Orders`.

Что требует ручной проверки:

- `CanExecute` для удаления проверяет `o is Order`, хотя выполнение ожидает `OrderWithCourier`.

## Работа с БД

Факты из кода:

- Для каждого запроса создается подключение через `_ds.CreateConnection()`.
- Подключение открывается асинхронно.
- Команды выполняются через `NpgsqlCommand`.
- Используются SQL-параметры `@Address`, `@Status`, `@CourierId`, `@Id`.

Пояснение:

Подключения создаются на время операции и закрываются через `await using`.
