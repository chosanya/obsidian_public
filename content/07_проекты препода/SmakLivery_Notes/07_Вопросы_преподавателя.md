# Вопросы преподавателя по SmakLivery

## Общая архитектура

### Что делает проект?

Это WPF-приложение для работы с заказами доставки. Оно показывает заказы из PostgreSQL, позволяет добавить, изменить и удалить заказ.

### Какие слои можно выделить?

- View: `MainWindow`, `AddOrEditWindow`.
- ViewModel: `MainViewModel`, `AddEditViewModel`.
- Model: `Order`, `OrderWithCourier`, `OrderStatus`.
- Data Access: `DbHelper`.

### Это MVVM?

Частично да. Данные и команды вынесены во ViewModel, но в `AddOrEditWindow` кнопки обрабатываются через `Click` в code-behind, поэтому MVVM не полностью чистый.

## WPF и Binding

### Что такое `DataContext`?

`DataContext` — объект, из которого WPF берет свойства и команды для Binding.

### Где задается `DataContext` главного окна?

В `MainWindow.xaml.cs`:

```csharp
DataContext = viewModel;
```

### Что делает `ObservableCollection`?

Она уведомляет интерфейс, что элементы коллекции добавлены или удалены. Поэтому `ListView`, привязанный к `Orders`, обновляется.

### Зачем нужен `OrderEnumDisplayConverter`?

Он преобразует значение `OrderStatus` в красивую строку из атрибута `[Display(Name = ...)]`.

## Команды

### Зачем нужен `RelayCommand`?

Чтобы не создавать отдельный класс команды для каждого действия. В него передаются делегаты `execute` и `canExecute`.

### Какие команды есть в `MainViewModel`?

- `AddOrder`.
- `EditOrder`.
- `DeleteOrder`.

### Что делает `CanExecute`?

Определяет, можно ли выполнить команду. Например, редактирование доступно только если выбран заказ.

## База данных

### Какая БД используется?

PostgreSQL.

### Какой драйвер используется?

Npgsql.

### Где строка подключения?

В [[Класс — DbHelper]]:

```csharp
Host=localhost;Username=postgres;Password=postgres;Database=smaklivery
```

### Какие SQL-объекты создаются при старте?

- PostgreSQL enum `order_status`.
- Таблица `order`.
- Таблица `courier`.

### Почему таблица `order` в кавычках?

`order` — ключевое слово SQL, поэтому имя таблицы экранируется как `"order"`.

## async/await

### Зачем здесь `async/await`?

Чтобы операции с БД не блокировали UI-поток WPF.

### Почему `async void` считается проблемным?

У `async void` сложнее отлавливать ошибки и ждать завершения операции. Обычно лучше возвращать `Task`, но обработчики событий WPF часто имеют `void`-сигнатуру.

## Проблемные места

### Что не так с `catch { }`?

Он полностью скрывает ошибку. Если запрос к БД упадет, пользователь может просто увидеть пустой список без объяснения.

### Что не так с `JOIN`?

Используется обычный `JOIN`, то есть `INNER JOIN`. Заказы без подходящего курьера не попадут в список.

### Что проверить в `DeleteOrder`?

`Execute` ожидает `OrderWithCourier`, а `CanExecute` проверяет `Order`. Из-за этого команда может быть недоступна не тогда, когда надо.
