# Речь для защиты SmakLivery

`SmakLivery` — это WPF-приложение для работы с заказами доставки. Оно показывает список заказов, позволяет добавить новый заказ, отредактировать существующий и удалить заказ. Данные хранятся не в файле, а в PostgreSQL.

При запуске приложения класс `App` вызывает `DbHelper.CreateDbAsync()`. Этот метод подключается к базе данных через Npgsql и создает необходимые объекты: перечисление PostgreSQL `order_status`, таблицу `order` и таблицу `courier`, если их еще нет.

Главное окно — это `MainWindow`. В нем есть `ListView`, который привязан к коллекции `Orders` из `MainViewModel`. Когда окно загружается, вызывается `LoadOrdersAsync()`, данные читаются из базы и добавляются в `ObservableCollection<OrderWithCourier>`. Благодаря `ObservableCollection` интерфейс автоматически видит изменения в списке.

Проект построен с использованием MVVM. View — это XAML-окна, ViewModel — это `MainViewModel` и `AddEditViewModel`, модели — `Order`, `OrderWithCourier` и `OrderStatus`. Команды реализованы через `RelayCommand`, который реализует интерфейс `ICommand`.

Для добавления и редактирования используется отдельное окно `AddOrEditWindow`. Оно создает `AddEditViewModel`, копирует данные заказа и при сохранении вызывает либо `DbHelper.AddOrderAsync()`, либо `DbHelper.EditOrderAsync()`.

Отдельно используется конвертер `OrderEnumDisplayConverter`. Он нужен, чтобы значения перечисления `OrderStatus` показывались пользователю не как `Accepted` или `Preparing`, а как строки из атрибута `Display`.

Важная тема проекта — асинхронность. Почти все операции с базой данных выполняются через `async/await`: создание таблиц, загрузка заказов, добавление, редактирование и удаление. Это нужно, чтобы интерфейс WPF не зависал во время обращения к PostgreSQL.

При этом в проекте есть места, которые я бы проверил отдельно. В `MainViewModel.LoadOrdersAsync()` есть пустой `catch`, который скрывает ошибки. В SQL используется `INNER JOIN`, поэтому заказы без курьера могут не отображаться. В таблице `courier` странно описан `FOREIGN KEY (id)` без ссылки на другую таблицу. Еще есть несоответствие в команде удаления: `CanExecute` проверяет `Order`, а фактически из списка приходит `OrderWithCourier`.

Главная ценность проекта для учебы в том, что он соединяет сразу несколько тем: WPF, MVVM, Binding, команды, `async/await`, PostgreSQL, Npgsql и SQL.
